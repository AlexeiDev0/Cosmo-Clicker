## Что реализовано

Google Mobile Ads 25.5.0 (Legacy API) и UMP 4.0.0. В debug всегда используются официальные демонстрационные App ID и rewarded ID Google. Тестовые показы не приносят дохода.

После обучения, в диалоге офлайн-дохода за отсутствие от 60 секунд доступна добровольная кнопка удвоения. Обычный доход уже начислен. Успешный rewarded callback добавляет только такую же сумму ещё раз. Идентификатор предложения и сумма хранятся вместе с балансом; повторный callback, старое предложение, reset и prestige не дают повторной награды. Получение бонуса подтверждается дисковой записью; при ошибке бонус откатывается и предложение остаётся доступным. Финальная запись редкой рекламной транзакции синхронная; её задержку нужно проверить на устройствах со слабым накопителем.

Симуляция и музыка приостановлены на время объявления. Возврат из объявления не создаёт новый офлайн-пакет. Один загруженный рекламный объект используется один раз; загрузка ограничена 45 секундами, повторная попытка запускается игроком. Объявления старше 55 минут перезагружаются. Нет автоматических полноэкранных показов или баннеров.

Для заявленной владельцем аудитории 13+ используется консервативное возрастное ограничение для всех пользователей: `AgeRestrictedTreatment.CHILD` (по таблице миграции Google соответствует старому TFUA=true), максимальный рейтинг объявления G, UMP under-age-of-consent=true. Возраст игрока не собирается; персонализация ограничена даже для взрослых. Это настройка обработки рекламных запросов, а не изменение заявленной аудитории игры на «младше 13». При добавлении определения возраста необходимо заново согласовать обработку несовершеннолетних и обновить политику.

В production перед запросами обновляется UMP, проверяется canRequestAds и при необходимости предоставляется пункт рекламной конфиденциальности в настройках. Для demo App ID конфигурации Privacy & messaging владельца нет, поэтому debug показывает только тестовую рекламу без production UMP. Это не тест реального сценария согласия; его надо проверить после настройки собственного приложения AdMob.

Политика версии 6 на EN/RU/ES и HTML описывает Google, рекламные данные, отдельное разрешение запросов, добровольные награды и ограничения удаления. Публичный URL: https://drona-salvage-privacy.slavfit.chatgpt.site . Email поддержки: alex.fitlin@gmail.com.

## Подключение реальной монетизации

1. Создать AdMob, зарегистрировать Android-приложение с package `com.orbitsalvagers.droneclicker` и создать Rewarded ad unit.
2. В AdMob настроить Privacy & messaging и выполнить проверки аккаунта, платёжного профиля и приложения.
3. Передать свои App ID (с `~`) и Rewarded ID (с `/`) в свойства Gradle:

```properties
ADMOB_APP_ID=ca-app-pub-ВАШ_PUBLISHER~ВАШ_APP
ADMOB_REWARDED_ID=ca-app-pub-ВАШ_PUBLISHER/ВАШ_REWARDED
```

Это пример формата, а не рабочие ID. Использовать локальные свойства Gradle или параметры `-P`; пароли подписи не передавать. Без обоих ID preReleaseBuild блокирует release. Если указан только один ID, формат неверен или переданы демонстрационные Google ID, Gradle остановит конфигурацию. Debug игнорирует production ID и использует demo только после отдельного разрешения рекламных запросов.

4. Проверить реальную конфигурацию на зарегистрированном тестовом устройстве. Не проверять реальные объявления собственными кликами без тестового режима.
5. Указать опубликованный URL политики и email поддержки в Play Console. Для AdMob разместить собственную строку app-ads.txt на корне домена сайта разработчика после получения publisher ID; не использовать заглушку. Публикация политики сама по себе не означает готовность app-ads.txt.
6. Заполнить Ads, Data safety по фактическому SDK, аудиторию 13+, рейтинг и карточку магазина. Проверить, что code 41 больше последнего загруженного; если в Play уже есть 41 или выше — увеличить.
7. Собрать подписанный AAB, загрузить в тестовый трек, проверить rewarded и UMP на устройстве, затем выпускать. При применимости выполнить закрытый тест 12 участников / 14 дней.
8. Связать AdMob с опубликованной карточкой и пройти проверку готовности рекламы. Настроить выплаты в собственном аккаунте.

## Ручная проверка

Автоматические проверки 05.10.2026: `testDebugUnitTest lintDebug assembleDebug --console=plain --max-workers=2` — успешно; 173 теста, 0 failures, 0 errors; lint — 0 ошибок, 197 предупреждений (в основном VectorRaster). Ранее замечание lint к получению перевода из LocalContext исправлено через stringResource. XML политики проверены, тексты EN/RU/ES совпадают с экспортами. Debug BuildConfig содержит только демонстрационный rewarded ID; release BuildConfig содержит ADS_ENABLED=false при отсутствии свойств владельца.

- Принять новую политику, пройти обучение, получить офлайн-пакет длительностью от минуты с ненулевым доходом флота.
- Убедиться, что обычный доход начислен до рекламы; после подтверждённого просмотра баланс растёт ровно на исходную сумму ещё один раз.
- Закрыть объявление раньше получения награды: бонус не выдаётся; обычный доход остаётся.
- Проверить отсутствие сети, повторную загрузку, быстрое двойное нажатие, background/foreground и пересоздание Activity.
- Убедиться, что звук и симуляция возвращаются, просмотр сам не создаёт новую офлайн-награду.
- После собственного AdMob проверить реальный UMP и merged manifest, Data safety, настройки приватности и release-ID.

Устройство для проверки в этой сессии не подключено. Компиляция и модульные тесты не подтверждают фактический показ объявления и правильность конфигурации аккаунта.
